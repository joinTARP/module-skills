# 认识 TARP

TARP 是一个由 AI 主持的桌面跑团应用。你扮演自己的角色，说出想做的事；主持描述场景、查阅规则，处理检定和行动结果。一个人也能开团，需要同伴时，可以把其他角色交给 AI 队友。

当前是 **v{{desktopVersion}}**。开始前，先安装并打开应用，再连接模型、载入模组。

当前桌面构建支持 Apple Silicon Mac、Windows x64 和 Linux x64。Linux 需要 WebKitGTK 4.1、GTK 3、Ayatana AppIndicator 和 librsvg，Windows 使用 WebView2；暂不提供 Intel Mac 安装包。

## 安装并打开应用

从[官网首页](/)选择 Windows x64、macOS Apple Silicon 或 Linux x64 安装包，并按安装包说明完成安装。下载入口始终指向最新发布版本。

打开 TARP，看到首页后，按[第一次冒险](first-adventure.md)连接模型和载入模组。如果提示配置文件损坏，按[启动故障处理](../reference/faq.md#应用提示配置文件损坏无法启动怎么办)处理。

可以从应用菜单打开「设置」，也可以使用 macOS 的 `⌘,` 或 Windows、Linux 的 `Ctrl+,`。

## 一局冒险怎样进行

主持先交代你在哪里、眼前发生了什么。接下来轮到你做决定，例如：

> 我蹲下来检查门锁，看看有没有被撬过。先不推门。

主持会查阅模组资料，判断这件事是否需要检定。需要掷骰时，程序生成骰点，聊天里会出现掷骰卡片，主持再根据规则和结果继续描述。你不用先学会一套输入指令，像平时跑团一样说明意图就行。

AI 队友会参与讨论，也会提出自己角色的行动。它们以玩家身份参与，由主持处理行动结果。想听某个队友的意见，可以用 `@角色名` 点名。使用方法见[AI 队友](../play/companions.md)。

骰点由程序生成，但规则怎样适用、剧情怎样回应，仍取决于主持模型的判断。遇到误判，可以把具体疑问告诉主持，必要时请它重新查阅规则。当前版本还不支持真人在线联机。

## 模组和存档里有什么

模组是一份文件夹，里面放着故事、规则、人物、地点和物品。它还会说明哪些资料对玩家可见、哪些数值可以在游戏中改变。

开始冒险时，应用会复制一份模组供本局使用。主持按需要读取其中的资料，把生命值、物品和场景等变化写进本局存档。下一次行动会读取更新后的状态，不会重新使用角色卡的初始值。

例如，你受了伤，主持把新的生命值保存到角色文档；之后再查看角色卡，就会看到这个数值。只有模组允许修改的字段才能写入，保存前也会检查数据格式。

源模组和本局存档分开保存。之后修改源文件，不会直接改动已经开始的冒险。已有冒险可[手动同步模组](first-adventure.md#同步已有冒险的模组)继续测试资料与规则；要验证完整选角或开场流程，仍需新建一局。

## 打开应用后准备什么

- **模型连接**：在「设置 → 模型配置」连接服务商，再到「设置 → 冒险默认设置」选择新冒险的默认主持模型。也可以进入冒险后单独选择，详见[连接模型服务](models.md)。
- **一份可玩的模组**：把完整的模组文件夹放进模组保存路径。目录摆放和开局步骤见[第一次冒险](first-adventure.md)。

模型费用和可用额度取决于你连接的服务及账户。主持、队友都会调用模型；队友判断是否需要发言时也会产生调用，即使最后保持沉默。

## 资料保存在哪里

模组和冒险存档保存在本机，位置和备份方法见[常见问题](../reference/faq.md#存档在哪里怎样备份)。

使用 AI 时，相关对话、规则和游戏资料会发送给你连接的模型服务；开启语音朗读后，待朗读文字会发送给语音服务。本地保存并不意味着这些功能可以离线运行。

如果你想写自己的故事，先看[模组目录结构](../modules/structure.md)。应用目前负责读取和展示模组，内容仍需要用外部编辑器维护。
