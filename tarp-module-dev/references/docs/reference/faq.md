# 常见问题

## 没玩过跑团，能直接开始吗？

可以。你扮演一个角色，用语言说出想做的事；主持描述周围的情况，遇到结果不确定的行动时，按模组规则处理。

不用先学会一整套规则。先选一份准备好角色和开局的模组，试着写下一条具体的行动：

> 我把灯举到门锁旁，看看锁孔附近有没有划痕。

接下来根据主持的回复继续行动。第一次体验，从[安装并打开应用](../getting-started/introduction.md#安装并打开应用)开始，再按[第一次冒险](../getting-started/first-adventure.md)连接模型和载入演示模组。

## 现在从哪里下载？支持哪些系统？

从[官网首页](/)下载最新发布版本，安装完成后按[第一次冒险](../getting-started/first-adventure.md)开始。

提供 Windows x64、macOS Apple Silicon 和 Linux x64 安装包。系统依赖见[安装并打开应用](../getting-started/introduction.md#安装并打开应用)。

## 源码采用什么许可证，可以商用吗？

TARP 桌面应用、共享模组核心与模组 CLI 的原创代码及文档采用 **GNU GPL v3（仅此版本，`GPL-3.0-only`）**。允许商业使用；分发应用或修改版时，应遵守保留版权与许可声明、提供完整对应源码等要求，具体以 [GPL v3 完整条款](https://www.gnu.org/licenses/gpl-3.0.html)为准。

第三方依赖、模组、规则和素材保留各自的授权条件，不因应用采用 GPL 而自动改变。

## 使用 AI 会产生哪些费用？

AI 主持、AI 队友和语音朗读使用你连接的服务，调用费用或用量限制取决于服务商和账户方案。

一条行动可能让主持多次查阅资料、调用工具，因此模型用量不只取决于最后显示的回复长度。AI 队友判断要不要发言时也会调用模型，即使最后没有发言。

想先控制用量，可以只保留一名队友，调低它的互动主动性，并按需要开启语音朗读。连接方式见[模型服务](../getting-started/models.md)，队友设置见[AI 队友](../play/companions.md)。

## 资料在本地，为什么还需要联网？

应用在本机管理模组、冒险存档和笔记。使用远程模型时，相关对话、规则和游戏资料会随请求发送给你连接的模型服务；语音朗读会把待朗读的文字发送给语音服务。

查看本地模组不需要调用模型。要让主持或队友回复，仍需有可用的模型连接。若使用自定义兼容服务，也需要它支持当前的对话和工具调用方式。

## 能和朋友在线联机吗？

当前版本还不支持真人在线联机。现在可以自己选择角色，再给其他角色分配 AI 队友一起玩。

## 修改昵称后，笔记还在吗？

在「应用设置 → 常规 → 玩家信息」修改昵称，离开输入框或按回车后自动保存。点击游戏侧栏小队列表中的成员可查看角色卡。

笔记按玩家身份保存。修改昵称后，你在当前冒险中的笔记仍会保留；其他玩家的笔记与草稿分别保存。自动保存和草稿恢复的方法见[冒险笔记](../play/notes.md)。

## 能使用自己的规则和故事吗？

可以。规则、人物、地点和物品等资料都由模组提供，用 Markdown、JSON 或 TOML 编写；字段、计算值和展示方式由模组的文档类型定义。

应用目前没有内置模组编辑器，源文件需要用文本编辑器或编程助手维护。先看[模组结构](../modules/structure.md)，再按需要添加[字段](../modules/doc-types.md)和[布局](../modules/layout.md)。规则怎么适用仍由主持模型判断，重要检定可以结合模组资料和公开骰点检查。

## 修改源模组，会影响正在玩的冒险吗？

新建冒险时，应用会复制一份模组供本局使用。之后修改模组库中的源文件，不会直接改变已经创建的冒险。

想保留进度使用修改后的资料，可在「冒险设置 → 模组与存档 → 模组同步」检查更新并同步；具体保留范围与限制见[同步已有冒险的模组](../getting-started/first-adventure.md#同步已有冒险的模组)。同步不会重播开局。想从头验证规则、选角或开场时，用更新后的源模组新建冒险，两局分别保存进度。

## 存档在哪里，怎样备份？

默认配置目录和冒险存档位置如下：

| 系统          | 配置目录               | 冒险存档                        |
| ------------- | ---------------------- | ------------------------------- |
| macOS / Linux | `~/.tarp/`             | `~/.tarp/sessions/`             |
| Windows       | `%USERPROFILE%\.tarp\` | `%USERPROFILE%\.tarp\sessions\` |

如果设置了 `TARP_HOME`，配置和存档会放在这个目录下。模组源文件另外保存在「设置 → 常规」显示的模组保存路径中，默认是系统「文档」目录下的 `tarp/modules`。

退出应用后，复制整个配置目录和模组源文件目录即可留一份备份。每个冒险目录都包含完整进度，备份时保留整个目录。配置目录还含有模型密钥和登录凭据，提交问题反馈时只提供相关错误信息和必要片段。

每段冒险的房间信息、玩家笔记、开局进度和队伍状态保存在该冒险目录的 `adventure.json`，按 `room`、`notes`、`launch`、`party` 分组；`contextSubscriptions` 另存主持与各队友的字段订阅清单。角色属性、物品和世界状态来自 `module/` 基础模组与 `game/` 本局覆盖，聊天保存在 `session.sqlite`，AI 会话保存在 `agent/`。房间级的模型、显示、聊天、压缩和语音设置独立保存在同目录的 `settings.json`；AI 队友的专属模型、主动性和声音保存在 `adventure.json` 的对应队友中，随队友一起保存和删除。两份文件都只支持标准 JSON；模型密钥仍保存在应用级配置目录，不写入冒险文件。

本局设置文件缺失或损坏时，依赖这些设置的功能会报告错误，冒险资料和笔记仍可读取。应用不会自动重置或覆盖坏文件，请按错误提示修正，或从备份恢复。

同目录的 `document-references.json` 保存资料之间的引用索引。它缺失或损坏时，应用会从当前资料重新构建；已经保存的换装、属性和进度以原始存档内容为准。

单独复制 `adventure.json`、聊天文件或某份角色卡不能保留完整进度，请备份整个冒险目录。

## 发出了消息，主持为什么没有回复？

先看是否使用了无点名的「聊天」模式。这种消息不会立即调用 AI，队友会在后续回应时收到加入后的近期公开聊天，跨场景也能参与讨论；需要主持解释规则或澄清描述时，从候选中点名「主持人」；需要推进剧情时，使用「行动」模式且不带点名。从候选中点名 AI 队友后，队友会排队回应，消息仍不会交给主持裁定。再看是否选择了「手动提交」：行动会先进入待提交队列，需要点击「继续」才交给主持。

如果消息已经提交，检查冒险使用的模型连接是否可用，并阅读界面的错误提示。更换默认模型不会自动替换已有冒险的主持模型；需要在该冒险的设置里重新选择。具体操作见[AI 主持](../play/ai-host.md)和[连接模型服务](../getting-started/models.md)。

## 为什么有些模组没有自建角色入口？

自建角色需要模组提供建卡流程。只有预设角色的模组不一定支持自建，先按已有开局方案选择角色即可。作者配置见[开局方案](../modules/game-starts.md)。

## 应用提示配置文件损坏，无法启动怎么办？

先看错误中给出的文件路径。应用级设置统一保存在 `~/.tarp/settings.json`，设置 `TARP_HOME` 时使用指定目录。文件按 `app`（常规设置）、`game`（玩家与默认模型）、`tts`（语音设置）分组，包含语音服务密钥，请妥善保管，不要公开分享。文件必须是有效的标准 JSON，不支持注释、尾逗号或 TOML，字段也要符合应用要求；无效配置会保留原文件并阻止启动，不会自动覆盖它。

可以用文本编辑器修正提示的字段，再重新启动。需要恢复默认设置时，先备份并移走这份 `settings.json`，应用会在下次启动时使用默认配置。模组保存路径、玩家昵称、默认模型与语音连接等设置需要重新配置，模组源文件和冒险存档另行保存。

模型服务配置另存于两份 JSON 文件：`models.json` 保存自定义服务商和模型定义，`auth.json` 由 pi 保存模型 API Key 与订阅登录凭据。只移走 `settings.json` 会保留这些模型连接；备份整个配置目录时也请保留这两份文件，并妥善保管凭据。

## 为什么某份存档没有出现在冒险列表中？

首页和历史冒险会跳过无法读取的存档，并继续显示其他冒险；被跳过的文件会保留在原位置。若冒险没有出现，先确认正在使用的配置目录，再检查对应冒险目录是否完整，必要时从备份恢复整个目录。存档位置和备份方法见[存档备份](#存档在哪里怎样备份)。

## 冒险结束后能重新开启吗？

结束后的冒险可以从历史记录重新开启，已经保存的游戏状态不会重置；后续如何继续由模组规则与主持解释。想从初始状态重玩时新建冒险。详见[结束冒险](../play/state.md#结束冒险)。

## 如何更新应用？

正式版启动后会在后台检查更新。发现新版时会显示提示，也可以打开「应用设置 → 常规 → 应用更新」，手动点击「检查更新」。检查不会自动下载或重启。

点击「下载更新」后可查看下载进度。更新准备完成后，先保存正在编辑的内容，再点击「重启更新」并确认。重启会停止当前的 AI 回复和语音播放；选择「稍后」可以继续使用当前版本。下载失败时，可检查网络后重新检查并重试。

自动更新获取 GitHub 的最新正式版，优先通过公共加速线路检查和下载，失败后自动尝试备用加速线路与 GitHub 直连。全部线路失败时会显示错误，可以稍后重试。开发版与预发布版暂不支持自动更新；没有更新功能的安装包需要先手动下载安装带更新功能的版本。
